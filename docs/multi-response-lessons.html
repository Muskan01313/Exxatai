Multi response forms

A multi response form is used when multiple responses will be submitted for the form. It is set up by choosing MultipleResponse as the Feature Type and ticking isMultiResponse. This part uses the example form Student Volunteer Record, with the Feature ID MSOT_SVR_PLNU, whose first field is Date of Initiation.

Steps at a glance

  1. In App Definition, select Feature Type, then MultipleResponse.
  2. Tick the isMultiResponse checkbox.
  3. Create a field at the top. In Description enter Date of Initiation, select the control type datepicker, and in Validations add required with the message Please select the date.
  4. Go to the Advanced sub-tab and enter the Property Name initiatedOn.
  5. Click Save.
  6. Save and publish the form in the particular tenant.
  7. Check the preview.
Before you startA new form should already exist in the Form Builder (Steps 2 and 6 of the Form Creation Guide). Custom is the Feature Type generally used. Choose MultipleResponse only when multiple responses will be submitted for the form.

Lesson 1 of 5

Select MultipleResponse as the Feature Type

On the Form tab, open the Feature Type dropdown in the App Definition group. It offers Custom, MultipleResponse and Standard. Select MultipleResponse.

In the example, the form name is Student Volunteer Record and the Form Name Abbreviation (Feature ID) is MSOT_SVR_PLNU. Label, Short label and Name show the form name.

Lesson 2 of 5

Tick isMultiResponse

In the option checkboxes of App Definition, tick isMultiResponse. It is unticked by default.

Lesson 3 of 5

Create the first field: Date of Initiation

Create a field at the top of the form (adding sections and fields is described in Step 7 of the Form Creation Guide). On the Main sub-tab:

  • Description: Date of Initiation
  • Control type: datepicker

The Control type dropdown in this screenshot lists these options, and the list continues below them:

Control types visible in the list
label, textbox, textarea, checkbox, radio, select, auto-fill, datepicker, timepicker, file-upload, esign, slider, formula, selection-list

Validation

Click Add Validation. Set Name to required, and choose the message Please select the date. The date message suits a date question.

Lesson 4 of 5

Enter the Property Name

Go to the Advanced sub-tab of the field and enter the Property Name initiatedOn. As with every question, the Property Name must be unique (Step 7 of the Form Creation Guide).

Lesson 5 of 5

Save, publish and check the preview

  1. Click Save.
  2. Save and publish the form in the particular tenant.
  3. Check the preview.

The preview shows how the Date of Initiation field is created.

Reference

Glossary

Terms used in this lesson set, taken from the Form Creation Guide.

Feature Type
A dropdown in the App Definition group with the options Custom, MultipleResponse and Standard. Custom is the type generally created; MultipleResponse is chosen when multiple responses are submitted for the form.
MultipleResponse (Feature Type)
The Feature Type chosen when multiple responses will be submitted for the form.
isMultiResponse
An option in App Definition that is ticked for a multi response form. It is unticked by default.
Form name abbr (Feature ID)
A unique abbreviation that keeps each form separate from the others. It is built from the initials of the form name, the university OU code and the domain. Only capital letters, small letters, numbers and underscores are permitted, with no spaces.
Label, Short label, Name, Detail
Fields in the App Definition group that are filled automatically with the name of the form when a new form is created.
Section
A group created by typing a name in Caption and clicking Add Section. Fields (questions) are added to a section.
Add Field
The button on a section that opens the field box, which has Main and Advanced sub-tabs.
Description
In the field box, the question that needs to be added.
Control type
A dropdown that sets the kind of field used for the question. Control types are covered separately.
datepicker
A control type used for a date question, such as Date of Initiation.
Validation (required)
A rule added with Add Validation. Choosing required makes the question mandatory, and a Message is then chosen to suit the question.
Property Name
A required entry on the Advanced sub-tab that identifies a question. It must be unique for each and every question.
fieldId
An identifier shown on the Advanced sub-tab. In the example it is the Feature ID of the form followed by the Property Name.
